# Netsky Code 0.1.0 verification

Release preparation used Bun 1.3.14, Node 24, an Apple Silicon Mac, isolated temporary configuration/databases, and the configured RunPod Qwen endpoint. Existing user settings, credentials, sessions, and running applications were not used as test fixtures.

## Automated checks

- Full TUI package: **216 passed, 1 existing skip, 0 failed**, 526 assertions. Includes a real `dialog.replace` regression for the asynchronous capability inventory and locked keyboard input.
- Host capability/MCP integration: **122 passed, 0 failed**, 498 assertions across 17 files. Covers built-in packs, live stdio/HTTP fixtures, reference lifecycle, session isolation, JSONC preservation, stale revisions, redaction, generated API integration, and evidence scoring.
- Core capability/plugin checks: **84 passed, 0 failed**, 312 assertions. Includes preserving the advertised tool snapshot through deactivation and probe-free human inventory.
- Core durable loops: **56 passed, 0 failed**, 230 assertions. Host loop commands/restart recovery: **7 passed, 0 failed**, 22 assertions.
- Installer, distribution, packaging, and ACP sessions: **54 passed, 0 failed**, 194 assertions. Archives preserve `LICENSE`; checksums reject missing/mismatched downloads; stable upgrades use the fork's stable release; the legacy executable and state are preserved.
- Manager file leases reuse the existing Core Flock implementation. Dedicated contention/recovery checks: 9 manager-store tests and 10 Core lock tests passed.
- App locale key/placeholder parity: **5 passed, 0 failed**, 979 assertions. Core, host, TUI, SDK, app, and UI package typechecks passed during release preparation. The app production build and embedded native CLI build passed.

Counts describe separately run suites and overlap; they are not a monorepo-wide test total. A stale end-to-end assertion was updated to materialize the next provider turn before waiting for shutdown, matching the new deferred-deactivation contract.

## Native acceptance

The first isolated native PTY run completed the keyboard flow: add a remote MCP, check its connection, create a user pack, activate it for one real session, leave another session inactive, obtain an unpredictable fixture value through a real Qwen tool call, and deactivate the pack. Management actions created no fabricated conversation messages.

Final acceptance passed on the embedded Netsky Code 0.1.0 binary. Through keyboard navigation it created a project remote MCP with concealed authentication and a global local-stdio MCP, attached both to the same project pack, enabled and disabled that pack, and verified session isolation and zero fabricated messages. The real Qwen response contained both unpredictable fixture values. The embedded web page identified itself as Netsky Code.

After warming four additional locations, **301 unique stream-delta events** were observed with no duplicate delivery; accumulated streamed parts exactly matched stored message text. The inventory API returned seven built-in packs in approximately **262 ms** in this run. Native captures, tool trace, and machine-readable results are retained locally under `tmp/netsky-native-h88shb/` in the release worktree (not published user data).

## Known baseline issue

The existing app test `desktop-native.test.ts` expects automatic `pa-PK` locale detection to resolve to `pa`, but it resolves to `en`. This was reproduced on the unchanged base commit `518397b`, independently of this release's identity-copy changes. It is not described as a passing check or silently fixed as part of this release.

## Scope

The release is an unsigned CLI distribution for macOS arm64/x64 and glibc Linux arm64/x64; x64 requires AVX2. External models, browsers, SDKs, scanners, and MCP services are separate dependencies. Standard global/current-project configuration is editable in the manager; custom/managed/ancestor sources retain their original configuration mechanism. Swarm and Agent Collabs are deliberately excluded.
